# PLAN-REQ-21 · FR-FEED-04(SVL) 폐기 표시 + FR-FEED-03 감사 누락 보정

> 출처: 현재 세션 대화 · 작성: 2026-09-22 · 상태: ✅ 완료

## 배경

REQ-20(게코 사육 환경 온습도 기록) 완료 후 `docs/TODO.md`에 남은 갭을 검토하던 중, 사용자가 몸무게(체중) 성장 그래프의 존재 여부를 물었고 이어서 "FR-FEED-04(🟡 Should Have, 게코 전용 SVL(몸길이) 성장 그래프)를 몸무게로 범위 변경해서 작업하자"고 제안했다.

그런데 Notion 원본(`요구사항` 데이터소스)을 직접 확인하니 **FR-FEED-04를 체중 용도로 바꾸는 것은 이미 존재하는 다른 요구사항과 중복된다**:

- **FR-FEED-03**(🔴 Must Have) — "체중 기록 및 꺾은선 그래프 시각화". 이게 실제 "체중 성장 그래프" 요구사항이고 FR-FEED-04와 별개로 이미 있었다
- **FR-FEED-04**(🟡 Should Have) — "게코 전용 — SVL(몸길이) 성장 그래프". SVL 전용이고, 관련 유저 스토리도 "SVL(주둥이~꼬리 길이)을 주기적으로 기록하고... 체중과 함께 성장을 입체적으로 추적"이라고 **체중과 별개 축(길이)** 임을 명시하고 있다

`GET /pets/{pet_id}/weight`(목록, `weight_change_rate`·`is_weight_warning` 파생 필드 포함)가 이미 FR-FEED-03이 요구하는 시계열 데이터를 충족한다. 그런데 `docs/TODO.md`(2026-09-21 "Notion FR 25건 전수 대조" 표기)는 **FR-FEED-03을 갭 목록에도 "확인 완료" 목록에도 올리지 않았다** — 전수 대조를 주장하면서 이 항목이 빠졌다. 참고로 Notion `요구사항` 데이터소스를 직접 세어 보면 실제로는 **23건**이라 "25건"이라는 표기 자체도 이번 조사에서 어긋난 것으로 드러났다(원인은 조사하지 않음 — 이번 REQ의 범위 밖).

이 사실을 사용자에게 보고했다. 사용자는 "체중 추이 확인 요구사항 번호가 이미 있으면 FR-FEED-04는 몸길이로 유지하고, 요구사항 자체를 폐기했다고 남겨 달라"고 최종 확정했다(대화 확정, 2026-09-22) — **FR-FEED-04의 정체성(SVL/몸길이)은 그대로 두고, 문구를 체중으로 바꾸지 않는다.** SVL 트래킹이라는 기능 자체를 이 프로젝트에서 하지 않기로 하고 그 사실만 요구사항 DB에 남기는 것이 이번 결정의 전부다. 체중 성장 그래프는 이미 있는 FR-FEED-03이 다루고(이미 백엔드로 충족됨), FR-FEED-04와는 별개로 손대지 않는다.

## 범위

**포함**

- Notion FR-FEED-04 페이지 — **SVL/몸길이라는 원래 정체성은 그대로 두고**, 본문에 폐기 사유 + FR-FEED-03 참조만 추가. 요구사항 DB에 별도 상태 속성이 없어(`우선순위`·`영역`·`요구사항ID`·`유저 스토리`뿐) 페이지 본문으로 남긴다
- Notion FR-FEED-04에 연결된 유저 스토리("게코로서, SVL을...") 페이지도 같은 사유로 폐기 표시
- `docs/TODO.md` 갱신 — FR-FEED-04를 갭 목록에서 제거(폐기됐으므로 더 이상 갭이 아님) + **FR-FEED-03을 "확인 완료" 목록에 신규로 명시**(이번에 드러난 감사 누락 보정, 근거: `GET /weight` + 파생 필드)

**제외**

- FR-FEED-04 문구를 체중으로 바꾸는 것 — 이번 결정으로 완전히 기각됨. FR-FEED-04는 SVL 그대로 두고 폐기만 표시
- 프론트엔드 꺾은선 그래프 렌더링 구현 — 이 저장소(petkok-api)는 백엔드 전용, 클라이언트 작업은 범위 밖
- 신규 백엔드 코드·엔드포인트 — weight 도메인은 이미 전종 공통이고 시계열+변화율 파생 필드까지 갖춰 추가 작업이 없다(대화 확정)
- SVL(몸길이) 자체 트래킹 — 이번 결정으로 이 프로젝트에서 완전히 폐기한다. 필요해지면 완전히 새로운 요구사항으로 다시 제안해야 한다(대화 확정)
- `docs/TODO.md`의 "25건" 표기 오차 원인 규명 — 이번 조사로 드러났지만 이 REQ의 목적(FR-FEED-03/04 정리)과 무관해 조사하지 않는다. 다음 전수 대조 때 실제 행 수(23건 확인 시점 기준)로 다시 세는 것을 권장
